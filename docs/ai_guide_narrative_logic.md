# AI音声ガイド 案内ロジック・アーキテクチャ仕様書 (AI Guide Narrative Logic Specification)

本ドキュメントは、インバウンド観光客向け「リアルタイム動的適応型 AI音声ガイドシステム」の案内ステップ、マルチエージェント協調フロー、およびプロンプト制約の完全な技術仕様書です。他のAIやエンジニアがシステムの振る舞い・設計思想を100%正確に理解できるよう定義されています。

---

## 1. システム概要と中核思想 (System Overview & Core Philosophy)

単なる観光地の歴史年表や客観的事実の読み上げではなく、**「旅行者の属性・関心」**と**「観光資源が持つ非代替的価値」**のギャップを橋渡しし、最終的に文化や歴史、職人技への**【深い尊敬（Path to Respect）】**へと昇華させる次世代音声ガイドシステムです。

### 📚 学術的・理論的基盤
1. **TOREモデル (サム・ハム教授)**:
   - **Thematic** (明確な1話1テーマ)、**Organized** (3〜5文の明快な構成)、**Relevant** (属性への価値翻訳)、**Enjoyable** (知的好奇心の刺激)。
2. **精緻化見込モデル (ELM: Petty & Cacioppo)**:
   - ユーザーの認知的余力・疲労度に応じて、**中心ルート (論理的深掘り・歴史技術)** と **周辺ルート (情緒・景観・心地よさ)** をリアルタイムに動的ギアチェンジ。
3. **認知的足場かけ理論 (ヴィゴツキーのScaffolding / 4象限モデル)**:
   - 第1象限【安心・共感】➔ 第2象限【発見・違和感】➔ 第3象限【文化的学び】➔ 第4象限【本質的敬意・職人技】。
4. **情報ギャップ理論 (ローウェンスタイン教授)**:
   - 各ステップの末尾に「知的好奇心を刺激する3つの問い」を提示し、ユーザー自身の自己決定 (User Agency) で次のナラティブを駆動。

## 2. マルチエージェント（Director-Actor）協調アーキテクチャ

単一の巨大プロンプトによるLLMの認知的過負荷や、Actorへのペルソナ直接渡しによるステレオタイプ暴走を根絶するため、**「ペルソナを分析し『比喩の処方箋（lens_metaphor）』と文体制約を発行するDirector AI」** と **「処方された比喩のみを使い、専属ナレーターとしてテキスト生成に集中するActor AI」** の2エージェント構成を採用しています。

```
                       【 ユーザーのタップ入力 】
                                  │
                                  ▼
┌──────────────────────────────────────────────────────────────────┐
│ 【 Step 1: Director AI (監督・処方箋発行＆ロジック制御) 】       │
│  ・Model: Gemini 2.5 Flash (responseMimeType: "application/json")│
│  ・Input: 観光地情報, 旅行者ペルソナ, 初期意図, 過去履歴, TurnCount│
│  ・Tasks:                                                        │
│    ① ユーザー属性を分析し、「語彙レベルとトーン」を指示         │
│       (若年層には硬い漢語を避け親しみやすい「年上の案内人」を指定)│
│    ② ペルソナに合わせた【比喩の処方箋 (lens_metaphor)】を1つ考案│
│    ③ 空間滞在ターン数（Turn Limit >= 3）判定と空間移動指示       │

└──────────────────────────────────────────────────────────────────┘
```

## 3. Director AI (ロジック＆処方箋エージェント) 仕様

### 3.1 入力データスキーマ (Input Context)
```json
{
  "spot_name": "浅草寺",
  "spot_location": "東京, 浅草",
  "target_language": "ja",
  "visitor_persona": "12歳、アニメ好き",
  "initial_theme_intent": "history",
  "current_step": "Chapter 1",
  "location_turn_count": 1,
  "selected_topic": "雷門の大提灯の秘密",
  "past_covered_topics": []
}
```

### 3.2 厳格遵守ルール (Rules)
1. **【文体とトーンの翻訳 (Tone Translation)】**:
   - ユーザーの年齢や属性（ペルソナ）を分析し、対象にとって最も理解しやすく知的好奇心を刺激する「語彙レベルとトーン」を割り出し、`actor_instruction` に指示として含める。
   - 若年層（例：12歳）の場合：大学教授のような硬い漢語は避け、ダイナミックで親しみやすい「年上の案内人」のトーンを指定する。ただし、子供番組のような過剰なテンション（「やっほー！」「〜だぜ！」）や感嘆符（！）の多用は厳禁とする。
2. **【比喩の処方箋 (Controlled Lens / lens_metaphor)】**:
   - 対象物のスケール感や魅力を伝えるため、ペルソナの関心領域に合わせた「比喩（Lens）」を1つだけ考案し、`lens_metaphor` に出力する。
   - 例: *「雷門の大提灯の大きさを、アニメの魔王の城のゲートやサッカースタジアムの入り口に例える」*
3. **【空間の強制遷移 (Spatial Turn Limit)】**:
   - `location_turn_count >= 3`（同一の物理空間で3ターン以上滞在）に達した場合、同一対象物の解説を強制終了する。
   - Actor に対して**「歩きながら次の空間（例: 雷門 ➔ 仲見世 ➔ 本堂 ➔ 境内）へ移動し、そこで新たな解説を始める」**よう命じ、選択肢（3択）も次の新空間のものに変更する。
4. **【選択肢のポートフォリオ生成】**:
   - 3つの選択肢を必ず以下の役割に分割し、行動を促す「疑問文（〜とは？ / なぜ〜か？）」で生成する。名詞の羅列は厳禁。
     - **[Deepen]**: 深い学び・歴史への問い
     - **[Explore]**: 視点を変えたライトな問い（写真、豆知識など）
     - **[Bypass]**: 別の場所への移動や休憩

### 3.3 出力データスキーマ (Strict JSON)
```json
{
  "actor_instruction": "ActorAIに対する、解説のテーマ、語彙レベル、トーンの厳格な指示（例：『〜について解説せよ。小学6年生でもわかる平易な言葉で、年上の案内人のトーンで。感嘆符の多用や過剰な子供扱いは厳禁』）",
  "lens_metaphor": "ActorAIが本文に1箇所だけ組み込むことを許可された具体的な比喩（例：『提灯の大きさをサッカースタジアムの入場ゲートに例えること』）",
  "next_choices": [
    { "type": "Deepen", "icon": "💡", "title": "歴史の深掘り", "prompt": "なぜこのような造りになっているのでしょうか？" },
    { "type": "Explore", "icon": "📸", "title": "注目の見どころ", "prompt": "この場所の景色や雰囲気をじっくり味わいませんか？" },
    { "type": "Bypass", "icon": "🚶‍♂️", "title": "次のスポットへ", "prompt": "気分を変えて周辺を散策してみませんか？" }
  ],
  "sources": [
    { "title": "公式情報源タイトル", "url": "https://..." }
  ]
}
```

## 4. Actor AI (ナラティブ生成エージェント) 仕様

### 4.1 役割と責務
歴史ある名所から下町の風景まで、その街の魅力を旅行者の心に翻訳して届ける「洗練された音声ガイドの専属ナレーター」です。ユーザーと会話をするチャットボットではありません。Directorからの指示に従い、魅力的で没入感のある「一方通行の語り（3〜5文のナレーション）」を提供します。**ペルソナ情報は完全隠蔽されており、Directorが処方した `lens_metaphor` のみを受け取ります。**

### 4.2 守るべき美意識と制約 (Core Principles & Constraints)
1. **【トーンの厳守とチャットボット化の禁止】**:
   - Directorからの指示（Instruction）にあるトーンと語彙レベルを完璧に再現する。
   - 「質問してくれてありがとう」「さあ、君はどう思う？」といった、ユーザーとの会話のキャッチボールを前提とした相槌やロールプレイは【厳格に禁止】。
2. **【レンズ（比喩）の正確な適用】**:
   - 与えられた `lens_metaphor`（比喩の処方箋）を、対象物のスケール感や導入の説明として、文章内に1箇所だけ自然に織り交ぜる。
   - それ以外の個人的な妄想や、指示されていないアニメ・スポーツ等の比喩を勝手に捏造することを固く禁じる。
3. **【空間の共有 (Visual First)】**:
   - 常に「今、ユーザーの目の前に広がっている景色」から語り始める。
   - 「いま目の前にある〜」という定型フレーズを機械的に反復することは避け、視線を上げさせたり、歩き出しを促したりと、ダイナミックな視点移動をテキストで表現する。
4. **【重複の排除 (Zero-Repetition)】**:
   - 過去の履歴を確認し、すでに語った事実や「ここは〜です」といった無駄な前置きの挨拶を一切繰り返さない。

### 4.3 入力と出力仕様
- **Input Data**:
  - `現在のスポット`: `{spot_name}`
  - `過去の対話履歴（要約）`: `{past_covered_topics}`
  - `Directorからの指示`: `{actor_instruction}`
  - `許可された比喩`: `{lens_metaphor}`
- **Output Format**:
  - 音声合成（TTS）エンジンにそのまま渡す、プレーンなテキスト本文（3〜5文程度）のみを出力。見出し、マークダウン、選択肢のテキストは一切含めない。

## 5. 3つの選択肢ポートフォリオ (Cognitive Sensor Portfolio)

毎チャプター提示される3択は、ユーザーの「次の認知的余力」を測定するセンサーとして機能します。

| 選択肢 | 役割（Portfolio） | 目的・対応ルート | 出力例 |
| :---: | :--- | :--- | :--- |
| **Choice 0** | **【発見・学び (Deepen)】** | 論理的深掘り・職人技・歴史背景（ELM中心ルート） | `💡 なぜ、この巨大な提灯が何百年も伝統を受け継いでいるのか？` |
| **Choice 1** | **【共感・探索 (Explore)】** | 視覚的な美しさ・写真アングル・豆知識（ELM周辺ルート） | `📸 提灯の真下から見上げる龍の彫刻、どんな迫力があると思いますか？` |
| **Choice 2** | **【脱出・行動 (Bypass)】** | 気分転換・食べ歩き・休憩・次のエリアへの移動 | `🚶‍♂️ 門をくぐって、賑やかな仲見世通りへ進んでみませんか？` |

## 6. 実証実験ログのデータ構造 (17-Column Chronological Schema)

実証実験・分析のためにエクスポートされるCSVデータは、以下の時系列対話プロセスに完全準拠しています。

1. `セッションID` (Session Identifier)
2. `生成日時` (YYYY/MM/DD HH:mm:ss)
3. `旅行者属性 (ペルソナ)` (Visitor Profile)
4. `観光資源名` (Heritage Site Name)
5. `所在地` (Location)
6. `言語` (Target Language: ja / en / zh / ru)
7. `選んだ初期の選択肢 (初回テーマ)` (Initial Choice: food / history / highlights)
8. `ステップ (Chapter)` (Chapter 1, 2, 3...)
9. `ユーザーが選択した選択肢 / トピック` (Selected Actionable Question)
10. `AI音声ガイド内容 (スクリプト)` (Actor Narrative Story Script)
11. `画面に提示された選択肢1` (Deepen Option)
12. `画面に提示された選択肢2` (Explore Option)
13. `画面に提示された選択肢3` (Bypass Option)
14. `Good / Bad の入力有無` (Micro-Feedback: 👍 Good / 👎 Bad / 未入力)
15. `0ms即時再生 (プリフェッチ)` (Prefetch Cache Hit: Yes/No)
16. `学び・発見フィードバック` (Overall Feedback: ✨感動 / 💡発見 / 🤔改善)
17. `フィードバック取得タイミング` (Feedback Triggered Chapter & Timestamp)
